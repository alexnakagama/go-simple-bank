# Go Simple Bank

A robust, modular, and production-ready RESTful API for simple banking operations, built with Go, PostgreSQL, and Gin. This project demonstrates best practices in Go architecture, configuration management, database migrations, and testing.

## Features

- Layered Clean Architecture for maintainability and testability
- JWT Authentication for secure endpoints
- PostgreSQL with safe, type-checked queries via `sqlc`
- Database migrations with `golang-migrate`
- Comprehensive testing with mocks and coverage
- Docker & Docker Compose for easy local development

---

## Tech Stack

- **Language:** Go 1.25+
- **Web Framework:** [Gin](https://github.com/gin-gonic/gin)
- **Database:** PostgreSQL 15+
- **Database Driver:** [lib/pq](https://github.com/lib/pq)
- **ORM/Queries:** [sqlc](https://github.com/kyleconroy/sqlc)
- **Migrations:** [golang-migrate](https://github.com/golang-migrate/migrate)
- **Configuration:** [Viper](https://github.com/spf13/viper)
- **Testing:** Go test, [Testify](https://github.com/stretchr/testify), [gomock](https://github.com/golang/mock)
- **Containerization:** Docker, Docker Compose

---

## Architecture Overview

- **Layered Clean Architecture:**
  - `api`: HTTP handlers, request validation, and routing.
  - `db/sqlc`: Data access layer, generated by sqlc from raw SQL queries.
  - `config`: Centralized configuration management.
  - `util`: Utility functions (e.g., random data generation, password hashing).
- **Configuration via `app.env`** using Viper.
- **Database migrations** and versioning.
- **Testable and modular**: All layers are independently testable.

Design Principles:
- Environment-driven config: All settings via `app.env` and Viper.
- Type-safe DB access: All queries are generated and checked by `sqlc`.
- Testability: Mocks and interfaces for all external dependencies.

## Getting Started

### Prerequisites

- Go 1.25+
- Docker & Docker Compose
- PostgreSQL client tools (`psql`, `createdb`, `dropdb`)

### Clone the Repository

```sh
git clone https://github.com/alexnakagama/go-simple-bank.git
cd go-simple-bank
```

### Setup Environment

Copy or edit `app.env` as needed:

```env
DB_PORT=5432
DB_HOST=localhost
DB_USER=root
DB_PASSWORD=secret
DB_NAME=root
DB_SOURCE=postgresql://root:secret@localhost:5432/root?sslmode=disable
DB_DRIVER=postgres
SERVER_ADDRESS=0.0.0.0:8080
TOKEN_SYMMETRIC_KEY=your-32-char-key-here
```

> **Note:** `TOKEN_SYMMETRIC_KEY` must be exactly 32 characters long. It is used as the symmetric key for signing PASETO tokens.

## Database Migrations

Start the database:

```sh
docker-compose up -d
```

Run migrations:

```sh
make migrate
```

Migration files are located in `internal/db/migrations/`. You can also create or drop the database with:

```sh
make createdb
make dropdb
```

---

## SQL Code Generation

SQL queries are in `internal/db/query/`. Run the following to regenerate Go code in `internal/db/sqlc/`:

```sh
sqlc generate
```

---

## Mock Generation

Mocks for the database interface are generated with [gomock](https://github.com/golang/mock). To regenerate them after changing the DB interface:

```sh
make mock
```

or directly:

```sh
mockgen -package mockdb -destination internal/db/mock/store.go github.com/alexnakagama/go-simple-bank/internal/db/sqlc Store
```

## API Endpoints

### Authentication

| Method | Endpoint        | Description         |
|--------|-----------------|---------------------|
| POST   | `/users`        | Register a new user |
| POST   | `/users/login`  | Login and get token |

### Accounts

| Method | Endpoint        | Description                                        |
|--------|-----------------|---------------------------------------------------|
| POST   | `/accounts`     | Create a new account (requires auth)              |
| GET    | `/accounts/:id` | Get account by ID (requires auth)                 |
| GET    | `/accounts`     | List accounts — params: `page_id`, `page_size`    |

### Transfers

| Method | Endpoint     | Description                              |
|--------|--------------|------------------------------------------|
| POST   | `/transfers` | Create a transfer between accounts (requires auth) |

### Examples

**Register a user:**

```sh
curl -X POST http://localhost:8080/users \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"secret123","fullname":"Alice","email":"alice@example.com"}'
```

**Login:**

```sh
curl -X POST http://localhost:8080/users/login \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"secret123"}'
```

**Create an account:**

```sh
curl -X POST http://localhost:8080/accounts \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <your_token>" \
  -d '{"currency": "USD"}'
```

**Get an account:**

```sh
curl http://localhost:8080/accounts/1 \
  -H "Authorization: Bearer <your_token>"
```

**List accounts:**

```sh
curl "http://localhost:8080/accounts?page_id=1&page_size=5" \
  -H "Authorization: Bearer <your_token>"
```

**Create a transfer:**

```sh
curl -X POST http://localhost:8080/transfers \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <your_token>" \
  -d '{"from_account_id": 1, "to_account_id": 2, "amount": "100", "currency": "USD"}'
```

## Testing

Run all tests:

```sh
make test
```

or:

```sh
go test -v ./...
```

- Tests use the same `app.env` configuration.
- Mocks are generated for DB and external dependencies.
- Main test setup is in `internal/db/sqlc/main_test.go`.
